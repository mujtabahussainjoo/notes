
### Summary: Packaging a Workflow as a Plugin with Skills, Custom Commands, and Marketplace Installation

#### Introduction
This summary explains how to package workflows in Claude Code so that other team members can easily install and use them. It covers skills, custom commands, and plugins, focusing on making the setup simple and effective.

### Key Concepts

1. **Skills: Reusable Workflows**
   - **What Are Skills?** Skills are small, reusable workflows stored in a file called **SKILL.md**. These skills are placed in a folder named **.claude/skills**.
   - **How They Work:** When you want to use a skill, Claude Code looks for it in that folder and runs the steps outlined in the SKILL.md file.

   **Example:**
   - You might have a skill called **deploy-validate** that checks deployment configurations. When you invoke this skill, it runs the checks automatically.

2. **Where Skills Can Run:**
   - Skills can be used in three main places:
     - **Claude Code:** When working in your terminal.
     - **Messages API:** When sending messages through an API.
     - **Agent SDK:** When using a software development kit.

   **Understanding the Difference:**
   - The same skill file can be run in these different environments, but what it can access and how it runs may change.

3. **Three Portability Rules for Skills:**
   - **Clear Descriptions:** Write a clear description for the skill so it loads correctly based on user requests.
   - **Avoid Local Dependencies:** Don’t assume local files or tools will be available. For example, a command that uses a local file path might work on your machine but fail on someone else's.
   - **Subagent Limitations:** If you use subagents, they won’t automatically inherit skills. You need to explicitly list any skills they should use.

4. **Custom Commands: Shortcuts for Procedures**
   - **What Are Custom Commands?** These are shortcuts that allow you to run specific procedures by name. For instance, you can set up a command like `/run-tests` that triggers a testing process.
   - **When to Use Them:** Use custom commands when you want a clear and predictable way to run frequent tasks.

5. **Plugins: Bundling Everything Together**
   - **What Are Plugins?** A plugin is a package that contains skills, hooks, subagents, and other components. It allows you to share a complete setup with your team.
   - **How to Install:** Teammates can install a plugin with a simple command, replacing manual setup steps.

   **Example of a Plugin Structure:**
   - Skills go into a **skills** directory.
   - Hooks, subagents, and settings are organized in their respective folders.
   - A manifest file describes the plugin and how to install it.

6. **Handling Environment Variables and Paths:**
   - **Avoid Absolute Paths:** Always use relative paths or environment variables to ensure that the plugin works on any machine. For example, use `$CLAUDE_PROJECT_DIR` to reference scripts in your project.
   - **Document Required Variables:** Make sure to list any environment variables your plugin needs so users know what to set up.

### Example Scenario

Imagine you’re creating a deployment validation plugin:
- You create a **SKILL.md** file that includes a command to run a validation script.
- You ensure the command uses a relative path, like this:

```markdown
---
name: deploy-validate
description: Validates a deployment configuration before release.
---
## Steps
1. Run the validation script: $CLAUDE_PROJECT_DIR/deploy-utils/validate.sh
2. If the script exits with a non-zero code, report the error to the user.
3. If validation passes, confirm the deployment configuration is safe to proceed.
```

### Conclusion
By using skills, custom commands, and plugins effectively, you can package workflows in Claude Code for easy installation and use. This simplifies the setup process for your team, ensuring everyone has access to the same tools and rules without needing to configure them manually each time.
