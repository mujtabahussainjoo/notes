## Tokens and context window (your “word budget”)

- A **token** is just a small chunk of text (like a syllable or short word) that Claude reads or writes; everything is measured and billed in tokens, not characters or words. [certsafari](https://www.certsafari.com/anthropic/claude-developer-foundations)
- The **context window** is your fixed token budget per request – it must fit your instructions, examples, conversation history, and Claude’s reply; if you overfill it, the request fails or gets cut off. [dev](https://dev.to/yashnigam/claude-certified-developer-foundations-certification-overview-4n07)
- **Sampling** means Claude doesn’t always pick the same next word; it sometimes chooses a different, still reasonable option, so the same prompt can give slightly different answers (**non‑determinism**), which is why tests should check “does this answer follow the rules?” instead of “is this exact sentence identical?”. [certsafari](https://www.certsafari.com/anthropic/claude-developer-foundations)

**Simple example:**  
Think of sending Claude a WhatsApp voice note with a strict time limit. The length limit is the **context window**, and the total talking time (your instructions + examples + its reply) must fit inside that limit.

## Claude models and reasoning modes

- There are different **Claude models** (like Opus, Sonnet, Haiku, Fable) with different power levels, speeds, and costs – heavier models are usually smarter but slower and more expensive. [anthropic](https://www.anthropic.com/news/claude-opus-4-6)
- Choosing a **model** (for example, a “stronger” Opus vs a “faster” Haiku) is different from turning on a **reasoning mode** like extended thinking; the mode changes *how* the chosen model thinks, not *which* model you’re using. [anthropic-partners.skilljar](https://anthropic-partners.skilljar.com/mso-foundations)

**Simple example:**  
Think of models as different cars (small, medium, big), and **extended thinking** as turning on “eco” or “sport” mode. You first choose the car, then choose the driving mode.

## Zero‑shot, one‑shot, and multi‑shot prompting

- **Zero‑shot prompting**: You give only instructions, no example. Good when the task is simple and clear.  
- **One‑shot prompting**: You give **one example** of the task you want. Good when the model needs to see the format once.  
- **Multi‑shot prompting**: You give **several examples**, so Claude can copy the pattern more reliably, but this costs more tokens and uses more of your context window. [anthropic](https://www.anthropic.com/news/prompting-long-context)

**Easy example – “write a friendly reminder email”**

- Zero‑shot: “Write a friendly reminder email to a coworker about tomorrow’s meeting at 3 PM.”  
- One‑shot: Show one example email first, then ask for a new one in the same style.  
- Multi‑shot: Show 3–4 different emails (formal, casual, short), then ask Claude to follow that pattern; better quality, but more tokens and cost.

## How developers access Claude in real projects

- You can call Claude either through an **SDK** (in languages like JavaScript, Python, etc.) or directly via **raw REST API**; both talk to the same backend, SDKs just add convenience helpers. [preporato](https://preporato.com/blog/what-is-ccdv-f-claude-certified-developer-foundations)
- For responses, you can use **synchronous** calls (wait for the full answer), **streaming** (receive the answer piece by piece as it’s generated), or **asynchronous / batch** patterns for high‑volume jobs where you don’t want to block a request while Claude is thinking. [anthropic-partners.skilljar](https://anthropic-partners.skilljar.com/mso-foundations)

**Easy example:**  
- Chat UI in a browser: likely **streaming** so the user sees tokens appear like typing.  
- Nightly batch job to summarize 10,000 logs: likely **async** or **batch** so you fire jobs and check results later.

## One simple “put it all together” example

Imagine you are building a support‑reply helper:

1. You choose a **model** (say, Sonnet) and maybe enable **extended thinking** for tricky tickets.  
2. You design a **prompt**:
   - A few rules (tone, length)  
   - Maybe 1–2 example replies (one‑shot or multi‑shot)  
3. You keep an eye on the **context window**:
   - System prompt + rules  
   - Past conversation with the customer  
   - Your examples  
   - Space for Claude’s reply  
4. You call Claude via an **SDK** from your backend, probably using **streaming** so the agent sees the answer appear live.  
5. You accept that replies are **non‑deterministic**:
   - Two calls may give slightly different wording  
   - Your tests check “Does it include the key info and follow the rules?” not “Is this sentence identical?”

This is exactly the kind of thinking this module trains: understanding tokens, context, sampling, model choice, prompting style, and API patterns at a practical, everyday level. [dev](https://dev.to/yashnigam/claude-certified-developer-foundations-certification-overview-4n07)
