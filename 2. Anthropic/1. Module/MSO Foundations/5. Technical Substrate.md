## Simple Summary: How Developers Talk to Claude

Developers can ask Claude to do things using code. There are different ways to do this, and each has its own use. The main ideas are: **how you connect**, **how you get the answer**, and **how you handle many requests at once**. [platform.claude](https://platform.claude.com/docs/en/cli-sdks-libraries/overview)

***

## 1) Two Ways to Connect: SDK or Raw REST

### Raw REST (Direct HTTP calls)
- You send an HTTP request (like a web request) to Claude’s API with your API key and a JSON message.
- You get a JSON response back.
- You can do this from any programming language that can make HTTP requests. [platform.claude](https://platform.claude.com/docs/en/api/overview)

### SDK (Software Development Kit)
- An SDK is a ready-made code library (for Python, TypeScript, etc.) that wraps the same REST API.
- It handles:
  - Logging in (authentication)
  - Building the request
  - Retrying if something fails
  - Reading the response
- You write less boilerplate code. [platform.claude](https://platform.claude.com/docs/en/cli-sdks-libraries/overview)

**Key point:** SDK and raw REST both reach the **same API and same model**. SDK just makes life easier. [claudearchitectcertification](https://claudearchitectcertification.com/concepts/technical-fundamentals-sdks-and-websockets)

**Simple example (idea only):**

- Raw REST (concept):
  ```text
  POST [https://api.anthropic.com/v1/messages](https://api.anthropic.com/v1/messages)
  Headers: API key, content-type
  Body: { "model": "claude-...", "messages": [...] }
  ```

- SDK (Python-like idea):
  ```text
  client = Anthropic(api_key="...")
  response = client.messages.create(model="claude-...", messages=[...])
  ```

Same thing under the hood, but SDK is cleaner. [platform.claude](https://platform.claude.com/docs/en/cli-sdks-libraries/overview)

## 2) How You Get the Answer: Sync, Streaming, Async

### Synchronous (Wait for full answer)
- You send a request and **wait** until the full response is ready.
- Good for:
  - Short answers
  - Background jobs where no user is waiting
- Bad for:
  - Long answers with a user staring at a blank screen [thestackunderflow](https://thestackunderflow.com/tutorials/batch-processing-llm-cost/)

**Idea:**
```text
Send request → wait → get full answer → continue
```

### Streaming (Answer piece by piece)
- Claude sends the answer **in small pieces** as it generates them.
- Your code shows each piece immediately to the user.
- Feels faster and more responsive, especially for long answers. [claudearchitectcertification](https://claudearchitectcertification.com/concepts/technical-fundamentals-sdks-and-websockets)

**Idea:**
```text
Send request → get piece 1 → show it
            → get piece 2 → show it
            → ...
            → done
```

Use streaming when a human is watching and you want them to see text appear live. [thestackunderflow](https://thestackunderflow.com/tutorials/batch-processing-llm-cost/)

### Asynchronous (Non-blocking calls)
- Your code starts a request and **does not freeze** while waiting.
- In Python: use an async client (`AsyncAnthropic`) with `await`.
- In TypeScript: the normal client uses Promises, so you `await` calls.
- Your app can do other work while waiting for Claude. [claudearchitectcertification](https://claudearchitectcertification.com/concepts/technical-fundamentals-sdks-and-websockets)

**When to use:**
- Many requests at once
- You want your app to stay responsive
- You care about concurrency, not just one call [tokenmix](https://tokenmix.ai/blog/ai-api-webhooks-async)

## 3) Handling Many Requests: Async vs Batch

These two patterns solve **different problems**. [thestackunderflow](https://thestackunderflow.com/tutorials/batch-processing-llm-cost/)

### Async (Concurrent real-time calls)
- You still call the normal API, but in a non-blocking way.
- Each request is processed in real time.
- Good when:
  - Users are waiting
  - You need results within seconds
  - You want to run many calls at once without freezing your app [thestackunderflow](https://thestackunderflow.com/tutorials/batch-processing-llm-cost/)

### Batch (Offline bulk jobs)
- You send **many requests together** as one batch job.
- You get an ID, then later check (poll) when it’s done.
- Can take up to **24 hours**, but costs about **half** per token. [thestackunderflow](https://thestackunderflow.com/tutorials/batch-processing-llm-cost/)

**Good for:**
- Large offline jobs (e.g., classify 10,000 documents)
- Evaluation runs
- Reports, ETL pipelines
- Anything where **cost matters more than speed** and no user is waiting [thestackunderflow](https://thestackunderflow.com/tutorials/batch-processing-llm-cost/)

**Not good for:**
- Chat or anything where a user is waiting
- Jobs where each request depends on the previous one [thestackunderflow](https://thestackunderflow.com/tutorials/batch-processing-llm-cost/)

**Simple rule:**
- User waiting or needs fast response → **Sync or Async (real-time)**
- Huge volume, no rush, care about cost → **Batch** [thestackunderflow](https://thestackunderflow.com/tutorials/batch-processing-llm-cost/)

## Tiny Decision Guide (Layman Version)

**How to connect?**
- Want less code and easier setup → **Use SDK**
- Need full control or using a language without SDK → **Use raw REST** [platform.claude](https://platform.claude.com/docs/en/cli-sdks-libraries/overview)

**How to get answers?**
- Short, background tasks → **Synchronous**
- Long answers, user watching → **Streaming**
- Many calls, app must stay responsive → **Async** [thestackunderflow](https://thestackunderflow.com/tutorials/batch-processing-llm-cost/)

**Many requests?**
- Real-time, user-facing → **Async concurrent calls**
- Big offline job, cost-sensitive, no rush → **Batch API** [thestackunderflow](https://thestackunderflow.com/tutorials/batch-processing-llm-cost/)

## Simple Diagram (Text)

```
Connect:
  [Your Code] --SDK--> [Claude REST API]
  [Your Code] --HTTP--> [Claude REST API]

Get answer:
  Sync:     [Send] ----wait----> [Full response]
  Stream:   [Send] -> [part] -> [part] -> ... -> [Done]
  Async:    [Send] (app does other work) -> [Response later]

Many requests:
  Async:  [Call 1] [Call 2] [Call 3] ... (all in real time)
  Batch:  [Send 1000s together] -> wait minutes/hours -> [Get all results]
```

More control = more code. More convenience = use SDK. Faster feel = stream. Cheaper bulk = batch. [platform.claude](https://platform.claude.com/docs/en/cli-sdks-libraries/overview)
