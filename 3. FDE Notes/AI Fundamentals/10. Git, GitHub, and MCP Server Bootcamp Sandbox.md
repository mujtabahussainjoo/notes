# Git, GitHub, and MCP Server Bootcamp Sandbox

## 1. What this bootcamp teaches

This bootcamp connects three important developer concepts:

- **Git**: Version control on your local computer.
- **GitHub**: A platform for hosting repositories and collaborating.
- **MCP Server**: A standard way for AI applications to use tools and data.

The main goal is to build a small sandbox where you can:

- Create and manage a Git repository.
- Push code to GitHub.
- Work with branches and pull requests.
- Connect an AI client to Git or GitHub through MCP.
- Let an AI assistant inspect code and perform controlled development tasks.

MCP is an open standard for connecting AI models with external data sources and tools. GitHub provides and maintains its own official MCP server. [web:16][web:19]

## 2. Git in simple words

Git records changes to files over time.

Think of Git as a detailed history of your project:

```text
Project files → Commit 1 → Commit 2 → Commit 3
```

Each commit is a saved checkpoint. You can inspect changes, return to an earlier version, and work safely on separate branches.

### Important Git terms

| Term | Simple meaning |
|---|---|
| Repository | A project tracked by Git |
| Working tree | Files currently present on your computer |
| Staging area | Changes selected for the next commit |
| Commit | A saved snapshot with a message |
| Branch | An independent line of development |
| Merge | Combining changes from branches |
| Remote | A repository hosted somewhere else |
| Clone | Copying a remote repository to your computer |
| Pull | Downloading and integrating remote changes |
| Push | Uploading local commits to a remote repository |
| Tag | A named reference, often used for a release |

## 3. Basic Git workflow

```text
Edit files
   ↓
Check changes
   ↓
Stage changes
   ↓
Commit changes
   ↓
Push to GitHub
```

### Create a repository

```bash
mkdir mcp-bootcamp-sandbox
cd mcp-bootcamp-sandbox

git init
echo "# MCP Bootcamp Sandbox" > README.md

git add README.md
git commit -m "chore: initialize sandbox"
```

### Inspect the repository

```bash
git status
git log --oneline --decorate --graph
git diff
```

### Create and switch to a branch

```bash
git switch -c feature/add-demo
```

Older Git versions may use:

```bash
git checkout -b feature/add-demo
```

### Commit a change

```bash
git add .
git commit -m "feat: add MCP demonstration"
```

Use focused commits. A commit should usually represent one logical change.

## 4. GitHub in simple words

GitHub hosts Git repositories online and adds collaboration features.

GitHub is commonly used for:

- Remote repository hosting.
- Code review through pull requests.
- Issue tracking.
- GitHub Actions for CI/CD.
- Releases and tags.
- Project planning.
- Security scanning.
- Team permissions and governance.

Git is the version-control tool. GitHub is a service built around Git.

## 5. Connect a local project to GitHub

Create an empty repository on GitHub, then connect it to your local repository:

```bash
git remote add origin https://github.com/OWNER/mcp-bootcamp-sandbox.git
git branch -M main
git push -u origin main
```

Check the remote:

```bash
git remote -v
```

Clone an existing repository:

```bash
git clone https://github.com/OWNER/mcp-bootcamp-sandbox.git
cd mcp-bootcamp-sandbox
```

## 6. Branch and pull-request workflow

A practical team workflow is:

1. Update the local default branch.
2. Create a feature branch.
3. Implement one focused change.
4. Run tests and quality checks.
5. Commit the change.
6. Push the branch.
7. Open a pull request.
8. Review and update the branch.
9. Merge after checks pass.

Example:

```bash
git switch main
git pull --ff-only origin main
git switch -c fix/improve-readme

# Edit files here

git add README.md
git commit -m "docs: improve sandbox instructions"
git push -u origin fix/improve-readme
```

### Pull-request checklist

- The title explains the change.
- The description includes the reason and result.
- Tests or validation steps are documented.
- Secrets are not included.
- The diff is small enough to review.
- The branch is up to date when required.
- CI checks pass.

## 7. What is MCP?

**Model Context Protocol**, or MCP, is a client-server protocol that lets an AI application discover and call external tools.

```text
AI application / MCP client
          ↓
     MCP protocol
          ↓
MCP server with tools and resources
          ↓
Git, GitHub, filesystem, database, API, etc.
```

An MCP server does not replace Git or GitHub. It exposes selected capabilities so an AI client can use them in a standard way.

### MCP concepts

| Concept | Meaning |
|---|---|
| MCP host | The application containing the AI experience |
| MCP client | The component that connects to an MCP server |
| MCP server | Program exposing tools, resources, or prompts |
| Tool | An action the model can request |
| Resource | Data that can be read by the AI application |
| Prompt | Reusable instructions exposed by a server |
| Transport | How the client and server communicate |

## 8. Git MCP server

The reference MCP servers repository includes a Git server that can read, search, and manipulate Git repositories. It can be started with `uvx` or installed with `pip`. [web:20]

### Start the Git server

```bash
uvx mcp-server-git --repository /absolute/path/to/repository
```

Or:

```bash
pip install mcp-server-git
python -m mcp_server_git --repository /absolute/path/to/repository
```

Use an absolute repository path in the sandbox. Restrict the server to the repository that the AI should access.

### Example MCP client configuration

The exact configuration format depends on the MCP host. A common local-server format is:

```json
{
  "mcpServers": {
    "git": {
      "command": "uvx",
      "args": [
        "mcp-server-git",
        "--repository",
        "/absolute/path/to/mcp-bootcamp-sandbox"
      ]
    }
  }
}
```

Potential Git operations include:

- Inspecting repository status.
- Viewing commit history.
- Searching files.
- Reading diffs.
- Creating or modifying repository content.
- Working with branches, depending on the server and client configuration.

For a learning sandbox, begin with read-only operations before allowing writes.

## 9. GitHub MCP server

GitHub maintains an official GitHub MCP server. It can provide AI tools for repository management, code and file inspection, issues, pull requests, Actions, security analysis, and team collaboration. [web:16][web:19]

### Typical GitHub MCP use cases

- Search repositories and files.
- Read code and repository trees.
- Inspect commits and pull requests.
- Create or update issues.
- Review pull requests.
- Inspect GitHub Actions runs.
- Analyze code-scanning findings.
- Work with releases and repository metadata.

The exact tools available depend on the server version, host application, authentication, and enabled toolsets.

## 10. Remote GitHub MCP server

The official remote GitHub MCP server is hosted by GitHub. A commonly documented endpoint is:

```text
https://api.githubcopilot.com/mcp/
```

A VS Code-style configuration can look like this:

```json
{
  "servers": {
    "github": {
      "type": "http",
      "url": "https://api.githubcopilot.com/mcp/"
    }
  }
}
```

Remote access commonly uses OAuth or a GitHub Personal Access Token, depending on the MCP host. GitHub documents support across IDEs, Copilot CLI, the Copilot app, and selected GitHub.com agent features. [web:16][web:19]

## 11. Local GitHub MCP server with Docker

The official server publishes a Docker image:

```text
ghcr.io/github/github-mcp-server
```

A PAT-based local configuration may look like this:

```json
{
  "mcpServers": {
    "github": {
      "command": "docker",
      "args": [
        "run",
        "-i",
        "--rm",
        "-e",
        "GITHUB_PERSONAL_ACCESS_TOKEN",
        "ghcr.io/github/github-mcp-server"
      ],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_PAT}"
      }
    }
  }
}
```

Do not replace `${GITHUB_PAT}` with a real token in a file that may be committed.

An OAuth-based Docker configuration is also available in the official repository. Use the official installation guide for the current host-specific setup. [web:19]

## 12. Authentication and permissions

An MCP server acts using the permissions available to its credentials.

### PAT security rules

- Use the smallest required permissions.
- Prefer fine-grained tokens when available.
- Use separate tokens for separate projects.
- Keep tokens in environment variables or a secret manager.
- Never commit tokens to Git.
- Rotate tokens regularly.
- Revoke exposed tokens immediately.
- Review the MCP client's logs and configuration files.

Example:

```bash
export GITHUB_PAT="your-token"
echo "GITHUB_PAT" >> .env.example
```

Do not put the real value in `.env.example`. Put the real `.env` file in `.gitignore`:

```bash
echo ".env" >> .gitignore
```

## 13. Toolsets and least privilege

The GitHub MCP server supports toolsets that group related functionality. Examples include:

- `repos`
- `issues`
- `pull_requests`
- `actions`
- `code_security`
- `users`
- `git`

You can enable only the groups needed for your task:

```bash
docker run -i --rm \
  -e GITHUB_PERSONAL_ACCESS_TOKEN="$GITHUB_PAT" \
  -e GITHUB_TOOLSETS="context,repos,issues,pull_requests" \
  ghcr.io/github/github-mcp-server
```

You can also select individual tools when the server supports it:

```bash
docker run -i --rm \
  -e GITHUB_PERSONAL_ACCESS_TOKEN="$GITHUB_PAT" \
  -e GITHUB_TOOLS="get_file_contents,issue_read" \
  ghcr.io/github/github-mcp-server
```

GitHub recommends limiting toolsets because fewer tools can improve tool selection and reduce context usage. [web:16][web:19]

## 14. Read-only sandbox design

Start with a safe, read-only setup.

```text
AI client
   ↓
Git MCP server: read repository
   ↓
Local sandbox repository

AI client
   ↓
GitHub MCP server: read repository, issues, PRs
   ↓
GitHub API
```

Recommended first capabilities:

- Read repository tree.
- Read files.
- Search code.
- Inspect commit history.
- Read issues and pull requests.
- Read Actions status.

Avoid enabling these initially:

- Creating or deleting repositories.
- Merging pull requests.
- Pushing code.
- Triggering production workflows.
- Modifying branch protection.
- Writing secrets or credentials.

### Lab 4: GitHub MCP server

1. Connect the official GitHub MCP server.

5. Ask it to inspect a pull request.
6. Ask it to check the latest Actions run.


3. Confirm the target repository.

## 17. GitHub Actions connection

GitHub Actions automates checks whenever code is pushed or a pull request is opened.

A simple workflow could be:

```yaml
name: Tests

on:
  push:
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: pip install pytest
      - run: pytest
```

An AI connected through GitHub MCP may be able to inspect workflows, runs, jobs, and logs, depending on the enabled toolset and permissions. [web:19]

## 18. Common problems

### Authentication fails

Check:

- The token is valid.
- The token has the required permissions.
- The environment variable is available to the server process.
- The token was not accidentally copied with extra spaces.
- The MCP host supports the selected authentication method.

### The AI cannot see a private repository

Check repository access, token permissions, organization policies, and whether the authenticated account can access the repository directly.

### The MCP server exposes too many tools

Use an allow-list of toolsets or individual tools. Start with read-only capabilities and add write capabilities gradually.

### Git operations affect the wrong repository

Bind the Git server to one explicit repository path. Confirm the path before starting the server and avoid exposing a parent directory containing multiple projects.

### The AI gives an incorrect code summary

Ask it to cite file paths, line numbers, commits, or pull requests. Verify its answer against the repository and Git history.

### A GitHub write operation is dangerous

Require confirmation for creating, updating, deleting, merging, releasing, deploying, or triggering workflows. Use branch protection and required reviews as additional safeguards.

## 19. Recommended professional practices

- Use Conventional Commit-style messages such as `feat:`, `fix:`, `docs:`, and `chore:`.
- Keep pull requests small and focused.
- Protect `main` with reviews and CI checks.
- Add `.gitignore` before creating project files.
- Use pre-commit hooks for formatting and secret detection.
- Store credentials outside the repository.
- Use read-only MCP access for exploration.
- Enable only the MCP tools required for the task.
- Log tool calls and review side effects.
- Test AI-generated changes before merging.
- Treat AI output as a proposed change, not as verified truth.

## 21. Key takeaways

- Git tracks project history locally.
- GitHub hosts repositories and supports collaboration.
- Branches isolate work; pull requests support review.
- MCP gives AI clients a standard way to call tools.
- The Git MCP server focuses on local Git repositories.
- The official GitHub MCP server connects AI tools with GitHub capabilities.
- Start with read-only access and limited toolsets.
- Keep tokens secure and grant minimum permissions.
- Require human review for code changes and side effects.
