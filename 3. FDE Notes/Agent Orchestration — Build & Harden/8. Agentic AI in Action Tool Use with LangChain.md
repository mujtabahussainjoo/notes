# LangChain Tools and Agents — Simple Summary

## Main idea

A language model can understand and write text, but it is not always good at:

- Doing exact calculations.
- Finding the latest information.
- Checking facts.
- Using your company’s special rules or data.

A **tool** gives the agent an extra ability. It can be a Python function, calculator, search system, weather service, database, or business API.

### Simple example

Think of the language model as a smart assistant.

- The assistant understands your question.
- A calculator performs the exact math.
- A search tool finds current information.
- A weather tool checks weather data.
- The assistant combines the results and explains them to you.

```text
User asks a question
        |
        v
Language model understands the question
        |
        v
Chooses the correct tool
        |
        v
Tool performs the task
        |
        v
Agent explains the result
```

## Why tools are useful

Without tools, the model depends only on what it learned earlier. This can cause mistakes, especially with numbers and current information.

With tools, the agent can:

- Get accurate results.
- Use fresh information.
- Follow specific business rules.
- Work with external systems.
- Combine several steps to solve a difficult question.

### Example

Question:

```text
What is 15 × 23 + 45?
```

The language model may understand the question, but the calculator tool should perform the calculation.

```text
15 × 23 + 45 = 390
```

The model explains the answer, while the calculator does the exact work.

## Building a safe calculator tool

The course creates a calculator using a normal Python function and then connects it to LangChain.

The calculator allows only safe operations such as:

- Addition.
- Subtraction.
- Multiplication.
- Division.
- Remainder.
- Powers.
- Positive and negative numbers.

It does not allow the user or agent to run arbitrary Python code.

### Basic calculator example

```python
def add_numbers(a: float, b: float) -> float:
    return a + b

print(add_numbers(10, 5))
```

Output:

```text
15
```

This function can be turned into a LangChain tool:

```python
from langchain_core.tools import tool

@tool
def calculate(expression: str) -> str:
    """Calculate a safe mathematical expression."""
    try:
        result = safe_calc(expression)
        return str(result)
    except Exception as error:
        return f"Error: {error}"
```

The `@tool` instruction tells LangChain:

> “This function is an ability that the agent can use.”

### How the safe calculator works

```text
User: Calculate (12345 × 6789) + 98765
        |
        v
Agent changes the request into a math expression
        |
        v
Safe calculator checks the allowed operations
        |
        v
Calculator returns the exact answer
        |
        v
Agent shows the answer
```

The calculator also:

- Removes unnecessary spaces.
- Rejects expressions that are too long.
- Allows only numbers and approved operations.
- Stops invalid or unsafe input.
- Returns clear error messages.
- Prevents extremely large results from causing problems.

## Plain model versus tool-based agent

| Plain language model | Agent with calculator |
|---|---|
| Tries to calculate by recognizing patterns | Sends the calculation to a real function |
| May make mistakes with long expressions | Produces exact results |
| Cannot verify its calculation | Uses a repeatable process |
| Good for explaining the answer | Good for both calculating and explaining |

### Important lesson

A language model is good at language, but it should not be trusted as a calculator when exact results matter.

The better approach is:

```text
Language model understands
+
Tool calculates
=
Reliable answer
```

## Using search and Wikipedia tools

LangChain can also connect agents to ready-made tools.

### Search tool

A web search tool is useful for:

- Recent news.
- Current events.
- New product information.
- Latest technology updates.
- Facts that may have changed.

Example:

```text
Find the latest news about generative AI.
```

The agent uses the search tool instead of relying only on its stored knowledge.

### Wikipedia tool

Wikipedia is useful for:

- General background.
- Definitions.
- Historical information.
- Biographies.
- Basic explanations.

Example:

```text
Explain Retrieval-Augmented Generation.
```

The agent can use Wikipedia to retrieve a short background summary.

### Choosing the right tool

```text
Current or recent information?
        |
        v
Use web search

General background or history?
        |
        v
Use Wikipedia

Exact calculation?
        |
        v
Use calculator
```

The tool description is important because it helps the agent decide when to use each tool.

For example:

```python
Tool(
    name="Calculator",
    func=calculator,
    description="Use this tool for mathematical calculations."
)
```

The description works like a small instruction manual for the agent.

## Creating a custom weather tool

The course also shows how to create a tool for a specific business need.

The example uses a simple weather function:

```python
@tool
def get_weather(city: str) -> str:
    """Return weather information for a city."""
    weather_data = {
        "mumbai": {
            "condition": "Cloudy",
            "temperature": "30°C"
        },
        "delhi": {
            "condition": "Sunny",
            "temperature": "32°C"
        }
    }

    city = city.strip().lower()

    if not city:
        return "Please provide a city name."

    if city not in weather_data:
        return "Weather information is not available."

    data = weather_data[city]

    return (
        f"City: {city.title()}\n"
        f"Condition: {data['condition']}\n"
        f"Temperature: {data['temperature']}"
    )
```

Example question:

```text
What is the weather in Mumbai?
```

The agent calls `get_weather("Mumbai")` and receives structured information.

### Why mock data is used

The course first uses sample weather data instead of a real weather service because it is:

- Easy to understand.
- Predictable.
- Free from changing results.
- Not dependent on an internet connection.
- Useful for learning the tool process.

Later, the sample data can be replaced with a real weather API without changing the main agent design.

```text
Sample weather function
        |
        v
Learn how tools work
        |
        v
Replace sample data with a real API
```

## Creating a multi-tool agent

A multi-tool agent has access to several tools at the same time:

```text
Calculator
Web search
Wikipedia
Weather tool
```

The agent decides which tool to use based on the user’s question.

### Example 1: Math

```text
Question: What is 15 × 23 + 45?
```

The agent chooses:

```text
Calculator
```

### Example 2: Current fact and math

```text
Question: Who is the current president of France, and what is √144?
```

The agent may:

1. Use web search for the current president.
2. Use the calculator for the square root.
3. Combine both results into one answer.

### Example 3: Background and calculation

```text
Question: Explain Albert Einstein and calculate
299792458 ÷ 1000000.
```

The agent may:

1. Use Wikipedia for Einstein’s background.
2. Use the calculator for the number.
3. Present both results clearly.

## How the agent works

A tool-using agent normally follows this process:

1. Read the user’s question.
2. Understand what needs to be done.
3. Decide whether a tool is needed.
4. Select the correct tool.
5. Send the required input to the tool.
6. Receive the tool’s result.
7. Use another tool if necessary.
8. Give the final answer.

```text
Question
   |
   v
Understand the task
   |
   v
Choose a tool
   |
   v
Run the tool
   |
   v
Check the result
   |
   +---- Another task? ---- Yes ----> Choose another tool
   |
   No
   |
   v
Give final answer
```

## Important LangChain parts

| Part | Simple meaning |
|---|---|
| Language model | Understands language and plans the work |
| Tool | Performs a specific task |
| Prompt | Rules that guide the agent |
| Agent | Decides which tool to use |
| Agent executor | Runs the agent and tools step by step |
| Tool description | Explains when a tool should be used |

A simple agent setup looks like this:

```python
llm = ChatGoogleGenerativeAI(
    model="gemini-2.0-flash",
    temperature=0
)

tools = [calculate, get_weather]

agent = create_tool_calling_agent(
    llm,
    tools,
    prompt
)

executor = AgentExecutor(
    agent=agent,
    tools=tools
)
```

The `temperature=0` setting is used when predictable answers are preferred over creative answers.

## Key lessons to remember

1. A language model is not an expert at every task.
2. Tools give the agent reliable abilities.
3. A normal Python function can become a LangChain tool.
4. Use a calculator tool for exact mathematics.
5. Use web search for current information.
6. Use Wikipedia for general background.
7. Custom tools can contain company rules or connect to business APIs.
8. Mock data is useful for learning before using real services.
9. A clear tool description helps the agent select the right tool.
10. Multiple tools can be combined to solve complex questions.
11. Safe input checks are important when building tools.
12. The agent should use tools instead of guessing when accuracy matters.
