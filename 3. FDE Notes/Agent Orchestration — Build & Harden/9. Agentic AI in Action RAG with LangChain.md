# RAG with LangChain: Easy Summary

## What is RAG?

**RAG** means:

> Find useful information first, then ask the AI to create an answer from that information.

A normal AI model answers mainly from what it learned earlier. Sometimes it may give a confident but wrong answer. RAG helps by giving the AI trusted information before it answers.

### Simple example

Suppose you ask a company chatbot:

```text
How many vacation days do employees get?
```

A normal AI may guess.

A RAG system:

1. Searches the company’s HR policy.
2. Finds the section saying employees get 22 days.
3. Gives the answer based on that section.

```text
Question
   |
   v
Search trusted information
   |
   v
Give the information to the AI
   |
   v
Create a clear answer
```

## Why RAG is needed

Language models are good at understanding and writing, but they can:

- Make up information.
- Use old knowledge.
- Give incomplete answers.
- Invent statistics or references.
- Sound confident even when they are wrong.

RAG reduces these problems by using information from sources such as:

- Company documents.
- PDF files.
- Databases.
- Product catalogs.
- Customer reviews.
- Knowledge bases.
- Websites and APIs.

### RAG in one line

```text
RAG = AI reasoning + trusted information
```

RAG does not guarantee that every answer is perfect, but it gives the AI real information to use instead of forcing it to guess.

## RAG compared with other methods

| Method | What it does | Main limitation |
|---|---|---|
| Prompt writing | Gives the AI better instructions | Does not add new facts |
| Fine-tuning | Trains the model with new examples | Expensive and difficult to update |
| Manual checking | Humans verify the answer | Slow and difficult for many users |
| RAG | Finds current information before answering | Needs a good document and search system |

### Easy way to remember

- Prompt writing changes **how the AI speaks**.
- Fine-tuning changes **what the AI has learned**.
- RAG gives the AI **information to read before answering**.

## Main RAG pipeline

A RAG system normally follows these steps:

```text
Documents
   |
   v
Split into smaller parts
   |
   v
Convert each part into numbers
   |
   v
Store the numbers in a searchable database
   |
   v
User asks a question
   |
   v
Find the closest matching parts
   |
   v
Give those parts to the AI
   |
   v
Generate an answer
```

### Step 1: Documents

The system starts with information such as:

```text
Our remote-work policy allows employees to work from home
three days per week.
```

### Step 2: Splitting documents

Large documents are divided into smaller pieces called **chunks**.

```text
Large policy document
        |
        v
Small useful sections
```

This makes searching easier. If the document is not split, the system may retrieve too much unrelated information.

A small overlap between chunks can help preserve meaning when an important sentence is divided between two parts.

### Step 3: Embeddings

An embedding changes text into a group of numbers that represents its meaning.

For example:

```text
"How many vacation days are allowed?"
```

can match a document saying:

```text
"Employees receive 22 days of annual leave."
```

The words are different, but the meaning is similar.

You can think of embeddings as placing similar ideas near each other on a large map.

```text
Vacation question  ---- close to ----  Annual leave policy

Weather question   ---- close to ----  Weather report

Product price      ---- close to ----  Product catalog
```

### Step 4: Vector database

The number representations are stored in a vector database.

The database acts like the memory of the RAG system. It helps the system quickly find text with a similar meaning.

In the course, ChromaDB is used as the example vector database.

### Step 5: Retrieval

When the user asks a question, the system searches the vector database and selects the most useful chunks.

For example:

```text
Question: What is our remote-work policy?

Retrieved information:
- Employees can work from home three days per week.
- Security rules must be followed when working remotely.
```

### Step 6: Generation

The AI receives the question and the retrieved information.

It then creates a natural answer:

```text
Employees can work from home up to three days per week.
They must also follow the company’s remote-work security rules.
```

## Different search methods

### Similarity search

Finds the text that is most similar in meaning to the question.

```text
Question: How many holidays do I get?
```

It may find:

```text
Employees receive 22 days of annual leave.
```

### MMR search

MMR tries to find useful information without returning many repeated sections.

For example, instead of returning five similar paragraphs about vacation, it may return:

- The number of vacation days.
- The rules for applying.
- The conditions for carrying days forward.

### Hybrid search

Hybrid search combines:

- Meaning-based search.
- Exact word or keyword search.

This is useful when exact words matter, such as:

- Product codes.
- Employee IDs.
- Policy numbers.
- Legal case names.
- Technical terms.

## Basic RAG code example

The following is a simplified example:

```python
from langchain_core.documents import Document
from langchain_text_splitters import RecursiveCharacterTextSplitter

documents = [
    Document(
        page_content=(
            "Employees can work from home three days per week. "
            "They must follow company security rules."
        ),
        metadata={"source": "hr_policy"}
    )
]

splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,
    chunk_overlap=50
)

chunks = splitter.split_documents(documents)
```

Here:

- `documents` contains the original information.
- `chunk_size` controls the approximate size of each piece.
- `chunk_overlap` keeps a small part of the previous piece.

A simplified retrieval process may look like this:

```python
question = "How many days can employees work from home?"

relevant_chunks = retriever.invoke(question)

context = "\n".join(
    chunk.page_content for chunk in relevant_chunks
)

prompt = f"""
Answer using only the information below.
If the answer is not present, say you do not know.

Information:
{context}

Question:
{question}
"""

answer = llm.invoke(prompt)
print(answer)
```

The important idea is:

```text
Search first
+
Answer from the search result
```

## The RAG prompt

A good prompt tells the AI exactly how to behave.

```python
template = """
Use the information below to answer the question.

If the information does not contain the answer,
say that you do not know. Do not guess.

Keep the answer short and clear.

Information:
{context}

Question:
{question}

Answer:
"""
```

This prompt is useful because it:

- Tells the AI to use retrieved information.
- Discourages guessing.
- Keeps the answer focused.
- Provides places for the retrieved text and question.

## Conversational RAG

A basic RAG system treats every question separately.

Example:

```text
User: What is RAG?
User: How does it work?
```

The second question is unclear if the system does not remember the first question.

A conversational RAG system remembers the chat:

```text
User: What is RAG?
Assistant: RAG finds information before answering.

User: How does it work?
Assistant: RAG first searches relevant documents, then gives them
to the AI to create the answer.
```

### Conversational RAG diagram

```text
New question
    |
    v
Read previous conversation
    |
    v
Rewrite unclear question
    |
    v
Search relevant documents
    |
    v
Use documents + chat history
    |
    v
Give a connected answer
    |
    v
Save the new conversation
```

### Why rewriting is needed

The user may ask:

```text
How does it work?
```

The system uses the earlier conversation to change it into:

```text
How does RAG work?
```

Now the retriever can search correctly.

A memory object stores:

- The user’s messages.
- The assistant’s replies.
- The order of the conversation.

```python
from langchain.memory import ConversationBufferMemory

memory = ConversationBufferMemory(
    memory_key="chat_history",
    return_messages=True,
    output_key="answer"
)
```

## Multi-source RAG

Real companies usually store information in many places.

For example:

```text
Company documents
Product catalog
Customer reviews
Knowledge-base articles
Live web information
```

Multi-source RAG searches these sources and combines the results into one answer.

### Example

```text
Which product has the best rating, what do customers say about it,
and how much revenue did it generate?
```

The system may search:

1. Product catalog for the rating.
2. Customer reviews for opinions.
3. Financial reports for revenue.
4. The web for current market information, if needed.

```text
                 +------------------+
                 | Company files    |
                 +------------------+
                          |
+----------------+   +----v-----+   +------------------+
| Product data   |-->| RAG      |<--| Customer reviews |
+----------------+   | system   |   +------------------+
                     +----+-----+
                          ^
                          |
                 +--------+---------+
                 | Live web search  |
                 +------------------+
                          |
                          v
                    Final answer
```

## Smart source selection

The system can look for words that usually require current information.

Examples:

```text
latest
current
today
recent
news
price
weather
trends
updates
```

If the question contains one of these words, the system can add web search.

```python
def needs_web_search(question: str) -> bool:
    keywords = [
        "latest",
        "current",
        "today",
        "recent",
        "news",
        "price",
        "weather"
    ]

    question = question.lower()

    return any(word in question for word in keywords)
```

### Example

```text
What is our product price?
```

The system may search internal product data.

```text
What is the current market price?
```

The system may search internal data and live web information.

## Why showing sources matters

A reliable RAG system should show where the answer came from.

Example:

```text
Answer:
The product rating is 4.8, and customers mainly like its battery life.

Sources used:
- Product catalog
- Customer reviews
```

This helps users:

- Check the answer.
- Understand which data was used.
- Trust the system more.
- Find mistakes more easily.

## Important limitations

RAG improves answers, but it is not magic.

The result can still be poor if:

- The documents contain wrong information.
- The important text was not retrieved.
- The chunks are too large or too small.
- The search system selects unrelated text.
- The prompt is badly written.
- The AI ignores the retrieved context.

A useful rule is:

```text
Good documents
+ Good splitting
+ Good search
+ Clear instructions
=
Better RAG answers
```

## Final memory guide

Remember RAG with these five words:

```text
Split → Convert → Store → Find → Answer
```

- **Split:** Break documents into smaller pieces.
- **Convert:** Change the meaning of each piece into numbers.
- **Store:** Save those numbers in a searchable database.
- **Find:** Retrieve the pieces related to the question.
- **Answer:** Let the AI respond using those pieces.

The complete idea is:

> RAG gives the AI the right information before asking it to answer.

This makes AI systems more useful for company assistants, customer support, research tools, product search, HR chatbots, and many other real-world applications.
