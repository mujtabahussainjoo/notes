## 1. LangChain + Gemini: basic setup

LangChain is an open‑source framework that gives you building blocks (prompts, chains, tools, memory) for AI apps. [atlan](https://atlan.com/know/ai-agent/ai-agent-memory/what-is-langchain/)
In this course, Gemini is the model that actually “writes” the text, and LangChain is the wrapper that organizes prompts and memory.  

**Key steps:**

- Install `langchain`, `langchain-google-genai`, and `google-generativeai`.  
- Create a Gemini API key in Google AI Studio and store it securely (as a secret / environment variable).  
- Make a `ChatGoogleGenerativeAI` instance, e.g. `model_name="gemini-2.0-flash"` with `temperature=0.7` for creative but not crazy outputs.  

**Diagram: basic call**

```text
Your code → LangChain (chain) → Gemini model → Text response
```

## 2. Simple chain: motivational quote generator

Here you build a **single chain** that turns a profession into a motivational quote.

**Building blocks:**

- **PromptTemplate** – a reusable template like:  
  “Write a short motivational quote for a {profession}.”  
- **LLM (Gemini)** – generates the actual text.  
- **StrOutputParser** – pulls out the plain text from the response.

**Chain code pattern (conceptually):**

```text
chain = prompt_template
        → Gemini LLM
        → text parser
```

**Example:**

- Input: `profession = "teacher"`  
- Output: A friendly quote like “You plant seeds of knowledge…”  

You can reuse the same chain for `profession="coder"`, `doctor`, etc.

## 3. Sequential chain: ideas → summary

Next, you build a **two‑step pipeline**:

1. First prompt: generate **three creative ideas** about a topic.  
2. Second prompt: **summarize those ideas** in two simple sentences.

**Step 1 prompt example:**

```text
"Generate 3 creative ideas about: {topic}.
Return them as a numbered list."
```

**Step 2 prompt example:**

```text
"Here are some ideas: {ideas}.
Summarize them in two easy-to-understand sentences."
```

LangChain lets you pass the **output of the first chain as input to the second** automatically.

**Diagram: sequential chain**

```text
Topic
  ↓
Idea chain (3 ideas)
  ↓
Summary chain (2 simple sentences)
  ↓
Final answer
```

**Example topic:** “Using AI to improve school homework feedback.”  
- First chain: 3 creative homework-feedback ideas.  
- Second chain: a short, friendly summary you could show to teachers or students.

## 4. Chatbot without memory

Here you build a **basic chatbot** that does not remember anything between turns.

**Setup:**

- Use `PromptTemplate` and `LLMChain` for two prompts:  
  - First: “My name is {name}. Please remember it and greet me.”  
  - Second: “Do you remember my name?”  

Because there is **no memory**, each call is fresh:  
- In call 1, the bot greets you with your name.  
- In call 2, the bot says it doesn’t remember, because LangChain didn’t store the previous conversation.

**Diagram: no-memory chatbot**

```text
User message → Chain → Response
(no past messages stored)
Each turn is isolated.
```

This demo shows the limitation: the bot sounds smart but is still “forgetful.”

***

## 5. Chatbot with ConversationBufferMemory (full memory)

Next, you add **ConversationBufferMemory**, which stores the full chat history.

**Key pieces:**

- `ConversationBufferMemory(memory_key="chat_history", input_key="input", output_key="text", return_messages=True)`  
- Unified prompt that includes history, e.g.:  

```text
"Chat History: {chat_history}

Human: {input}
AI:"
```

- `LLMChain` with the LLM, prompt, and memory.

Now, every new response sees the previous messages in `chat_history`.

**Example flow:**

1. You say: “My name is Rahul. Please remember it and greet me.”  
2. Bot responds: “Nice to meet you, Rahul!” (and history is stored).  
3. You ask: “Do you remember my name?”  
4. Bot responds: “Yes, Rahul, I remember your name,” because the **memory buffer** holds earlier messages.

**Diagram: full memory**

```text
[All previous turns] → Memory buffer
          ↓
Prompt with chat_history
          ↓
LLM → Response
          ↓
Stored back into memory
```

Good for short conversations where remembering everything is fine.

***

## 6. Windowed memory with ConversationBufferWindowMemory

Finally, you use **ConversationBufferWindowMemory**, which remembers only the **last k messages** (a sliding window), not the entire history.

**Key config:**

```text
memory = ConversationBufferWindowMemory(
    memory_key="chat_history",
    input_key="input",
    output_key="text",
    k=2,           # remember only last 2 messages
    return_messages=True
)
```

Everything else (prompt, chain) is similar, but now **older messages get dropped** as the chat grows.

**Example scenario:**

1. You give your name → bot greets you (name is in memory).  
2. You ask about Mars → bot answers and still greets you by name (name is still in the last 2 turns).  
3. You ask about plants → bot answers, again with your name.  
4. You ask: “Do you remember my name?”  
   - If too many new turns happened and `k=2`, your original “My name is…” message may have dropped out.  
   - Then the bot **cannot** correctly recall your name anymore.

**Diagram: windowed memory (k = 2)**

```text
Full chat:
[Msg1: name] [Msg2: Mars] [Msg3: plants] [Msg4: follow-up]

Window (last 2 only):
[Msg3: plants] [Msg4: follow-up]

Older messages (like Msg1 with your name) are forgotten.
```

This is like **short-term memory**: useful when chats are long and you only want recent context.

***

## 7. Full vs windowed vs no memory (easy comparison)

| Type                        | What it remembers                        | Good for                         |
|-----------------------------|-------------------------------------------|----------------------------------|
| No memory                   | Nothing between turns                    | Simple, stateless tools          |
| Full ConversationBufferMemory | Entire chat history                      | Short chats, rich personalization |
| ConversationBufferWindowMemory | Only last *k* messages                   | Long chats, focus on recent context |
