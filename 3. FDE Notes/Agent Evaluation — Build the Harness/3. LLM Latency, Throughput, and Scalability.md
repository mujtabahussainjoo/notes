# LLM Speed, Traffic, and Scaling

This course explains how to make an LLM respond quickly, handle many users, and continue working when demand increases.

The main idea is:

> **A good LLM system must be fast enough, handle enough requests, and grow without becoming slow, expensive, or unreliable.**

## 1. Three Important Words

### Latency

**Latency** means how long the system takes to answer one request.

```text
User asks a question → System answers after 2 seconds
Latency = 2 seconds
```

Low latency is important for:

- Chatbots.
- Voice assistants.
- Live translation.
- Gaming.
- Emergency systems.
- Financial trading.

High latency makes users wait and may reduce trust.

### Throughput

**Throughput** means how many requests the system can handle in a period of time.

```text
System handles 100 requests in 10 seconds
Throughput = 10 requests per second
```

High throughput is important for:

- E-commerce websites.
- Customer-support systems.
- Content moderation.
- Large document processing.
- Streaming captions.

### Scalability

**Scalability** means the system can handle more users or work as demand grows.

```text
100 users today → 10,000 users during a sale
```

A scalable system continues working without becoming too slow or failing.

## 2. Simple Comparison

| Term | Simple meaning | Main question |
|---|---|---|
| Latency | Time for one answer | How fast is one response? |
| Throughput | Number of answers in a period | How many requests can it handle? |
| Scalability | Ability to grow | Can it handle more users later? |

## 3. What Affects Latency?

### Model size

Large models usually need more calculations.

```text
Small model → Faster response
Large model → Slower but possibly better response
```

### Hardware

Powerful GPUs, TPUs, and AI chips can make responses faster.

Old or weak hardware can create delays.

### Network speed

For cloud-based models, data travels between the user and the server.

Slow network:

```text
User → Slow network → Model → Slow network → User
```

This increases total waiting time.

### Batch size

Batch size means how many requests are processed together.

- Small batch: faster individual response.
- Large batch: better overall efficiency but may delay each request.

### Input and output length

Long prompts and long answers take more time.

### Pipeline steps

The entire path can add delay:

```text
Receive request
      ↓
Check user
      ↓
Search documents
      ↓
Call model
      ↓
Check answer
      ↓
Send response
```

Every extra step can increase latency.

## 4. Measuring Latency

There are two useful measurements.

### End-to-end latency

Measures the full user experience.

```text
Request sent → Network + processing + response received
```

### Inference latency

Measures only the model’s processing time.

```text
Input reaches model → Model generates output
```

End-to-end latency is usually more important to users.

### Simple Python example

```python
import time

start = time.time()

answer = "This is a sample model response."

end = time.time()

latency = end - start
print(f"Latency: {latency:.2f} seconds")
```

## 5. Example: Small and Large Models

Suppose two models answer the same question.

| Model | Response time | Answer quality |
|---|---:|---|
| Small model | 4.5 seconds | Acceptable |
| Large model | 12.9 seconds | More detailed |

The large model may be better, but it is not always the right choice.

For a live chatbot, 12.9 seconds may be too slow.

For legal research, the extra waiting time may be acceptable if the answer is much better.

## 6. How to Reduce Latency

### Model pruning

Remove parts of the model that are not very useful.

```text
Large model → Remove unnecessary parts → Smaller, faster model
```

### Quantization

Use smaller number formats for the model’s internal values.

Benefits:

- Less memory use.
- Faster calculations.
- Lower hardware cost.

### Knowledge distillation

Train a smaller model to copy the useful behavior of a larger model.

```text
Large teacher model
        ↓ teaches
Small student model
```

### Caching

Store answers to common questions.

```text
Same question → Return saved answer
```

This avoids calling the model again.

### Edge deployment

Run the model closer to the user.

```text
User in Kolkata → Nearby server → Faster response
```

Less distance usually means less network delay.

### Pipeline optimization

Remove unnecessary steps and improve the slow parts of the system.

### Load balancing

Spread requests across several servers.

```text
Users
  ↓
Load balancer
 ┌────┼────┐
Server 1  Server 2  Server 3
```

This prevents one server from becoming overloaded.

## 7. What Is Throughput?

Throughput is the number of requests processed per second or minute.

### Example

```text
50 requests completed in 21.35 seconds

Approximate throughput:
50 ÷ 21.35 ≈ 2.34 requests per second
```

Higher throughput allows a system to serve more users.

## 8. What Affects Throughput?

- Model size.
- GPU or TPU power.
- Batch size.
- Number of servers.
- Parallel processing.
- Network bandwidth.
- Data pipeline speed.
- Caching.
- Model optimization.

### Batch processing

Batch processing handles several inputs together.

```text
Request 1
Request 2
Request 3
Request 4
      ↓
Process together
```

This can improve hardware usage and throughput.

However, large batches may increase waiting time, so they are not always suitable for real-time systems.

### Parallel processing

Several processing units work at the same time.

```text
One request → GPU 1
One request → GPU 2
One request → GPU 3
```

This helps handle more requests.

### Asynchronous processing

The system starts work without making every request wait for the previous one to finish.

This is useful for:

- Large document jobs.
- Background processing.
- Report generation.
- High-volume workloads.

## 9. Example: Increasing Throughput

Suppose one server handles:

```text
2.34 requests per second
```

After adding another server:

```text
4.43 requests per second
```

The system processes more than before because the work is shared.

This is the basic idea of scaling.

## 10. What Is Scalability?

Scalability means increasing system capacity when demand increases.

### Vertical scaling

Make one machine more powerful.

```text
Small server → Bigger GPU and more memory
```

**Advantages:**

- Simple to understand.
- May be easy to set up.

**Disadvantages:**

- Hardware can become very expensive.
- There is a limit to how powerful one machine can be.
- One machine can still become a single point of failure.

### Horizontal scaling

Add more machines.

```text
One server → Two servers → Ten servers
```

**Advantages:**

- Can handle more users.
- Easier to expand gradually.
- Better protection if one server fails.

**Disadvantages:**

- More complex.
- Requires good networking.
- Work must be shared correctly.

### Hybrid scaling

Use both approaches.

```text
Powerful servers + additional cloud servers during peak demand
```

This can provide a balance between control, speed, and cost.

## 11. Scaling Challenges

Scaling an LLM can create problems.

### Infrastructure cost

More servers, GPUs, memory, and storage increase costs.

### Data movement

Large data must move between machines.

Slow data transfer can create a bottleneck.

### Synchronization

Multiple machines must remain coordinated.

### Model complexity

Large models are harder to run across many machines.

### Network bottlenecks

Even with many servers, one slow network connection can slow the whole system.

### Memory limitations

Large models need a lot of memory. Not every machine can hold them.

### Performance changes

Adding more machines does not always produce a perfect improvement.

## 12. Techniques for Better Scaling

- Add more servers when traffic increases.
- Remove extra servers when traffic decreases.
- Use load balancing.
- Use auto-scaling.
- Use cloud resources during peak demand.
- Compress the model.
- Use caching.
- Store data close to the application.
- Monitor performance continuously.
- Keep backup servers ready.
- Use hybrid on-premises and cloud systems.

### Auto-scaling example

```text
Normal traffic → 2 servers
High traffic   → 6 servers
Low traffic    → 2 servers
```

This saves money while maintaining performance.

## 13. Real-Time Applications

Real-time applications need fast answers.

Examples:

- Voice assistants.
- Customer-support chatbots.
- Autonomous vehicles.
- Financial trading.
- Emergency response.
- Healthcare systems.
- Games.
- Live captions.

### Why delay matters

```text
User speaks → Assistant answers after 1 second
```

This feels natural.

```text
User speaks → Assistant answers after 30 seconds
```

This feels broken.

In healthcare, emergency response, finance, and autonomous vehicles, a delay can cause serious harm.

## 14. Batch Size for Real-Time Systems

Batch size affects both speed and throughput.

| Batch size | Effect |
|---|---|
| Small | Faster individual answers, lower total efficiency |
| Large | Higher total throughput, slower individual answers |

For real-time systems, use smaller batches.

For background jobs, use larger batches.

## 15. Balancing Speed and Accuracy

Making a model faster can sometimes reduce its quality.

```text
More speed ←→ More accuracy
```

The right balance depends on the application.

| Application | Main priority |
|---|---|
| Live chatbot | Speed and acceptable accuracy |
| Medical support | Accuracy and safety |
| Legal research | Accuracy and explanation |
| Gaming | Very low delay |
| Overnight report | Throughput and low cost |
| Financial trading | Speed and accuracy |

## 16. E-Commerce Example

An online store uses an AI chatbot.

### Simple questions

```text
"What are your delivery charges?"
```

Use a small, fast model or a cached answer.

### Complex questions

```text
"Compare these five products and recommend the best one for a family."
```

Send the request to a larger, more capable model.

```text
User question
      ↓
Request router
 ┌────┴────┐
Simple     Complex
question   question
   ↓          ↓
Small model  Large model
```

This approach provides:

- Fast replies for simple questions.
- Better answers for difficult questions.
- Lower overall cost.
- Better customer experience.

## 17. Ethical LLM Deployment

Speed and scale are not enough. The system must also be responsible.

### Bias

The model may treat some groups unfairly because of biased training data.

### Privacy

Protect personal, financial, medical, and other sensitive data.

### Transparency

Users should understand:

- When AI is being used.
- What data is collected.
- How data is processed.
- What the model can and cannot do.

### Accountability

A responsible person or team must be answerable for the system’s results.

### Human review

Important decisions should not be made by AI alone.

### Good practices

- Use diverse training data.
- Run regular bias checks.
- Anonymize private information.
- Encrypt data.
- Control who can access data.
- Keep model documentation.
- Allow users to report problems.
- Monitor the model continuously.
- Prepare an incident response plan.

## 18. Reducing Cost with Settings

Model settings can affect:

- Response length.
- Processing speed.
- Throughput.
- Cost.

### Common settings

- `max_length`: Maximum output length.
- `max_input_length`: Maximum input size.
- `top_k`: Limits possible next-token choices.
- `top_p`: Controls the range of likely choices.
- `temperature`: Controls randomness.

### Simple example

```python
settings = {
    "max_new_tokens": 50,
    "top_k": 30,
    "temperature": 0.2
}
```

Shorter answers usually take less time and cost less.

### Practical rule

```text
Simple task → Short answer and smaller model
Complex task → Longer answer and stronger model
```

]

for request in requests:

## 20. Final Memory Guide

- **Latency:** Time taken for one response.
- **Throughput:** Number of responses handled in a period.
- **Scalability:** Ability to handle more users and work.
- **Pruning:** Remove unnecessary model parts.
- **Quantization:** Use smaller number formats to make the model lighter.
- **Distillation:** Teach a small model from a large model.
- **Caching:** Reuse saved answers.
- **Load balancing:** Share work across servers.
- **Vertical scaling:** Make one server stronger.
- **Horizontal scaling:** Add more servers.
- **Auto-scaling:** Add or remove servers automatically.
- **Edge computing:** Run the model closer to users.

> **A strong production LLM system must be fast for users, powerful enough for the task, able to handle heavy traffic, affordable to run, and safe to use.**
