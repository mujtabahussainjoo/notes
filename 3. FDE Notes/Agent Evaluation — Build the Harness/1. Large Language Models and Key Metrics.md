# Understanding and Evaluating LLMs

This course explains what large language models are, how they work, how to choose one, and how to measure whether it is useful.

The main idea is:

> **Choose an LLM based on your actual task, cost, speed, privacy, and quality—not only because it is large or popular.**

## 1. What Is an LLM?

An LLM is an AI system trained on a very large amount of text.

It can:

- Understand questions.
- Generate text.
- Summarize documents.
- Translate languages.
- Answer questions.
- Analyze feelings in reviews.
- Help write code and content.

### Simple example

```text
User: Summarize this customer review.

LLM: The customer liked the product's design but
was unhappy with its battery life.
```

An LLM does not think like a human. It learns patterns in text and predicts what words are likely to come next.

## 2. How an LLM Works

The basic process is:

```text
Human text
    ↓
Tokenization
    ↓
Numbers representing the text
    ↓
Embeddings
    ↓
Attention and transformer layers
    ↓
Predicted answer
```

### Tokenization

Tokenization breaks text into small parts called tokens.

```text
"AI is helpful"
        ↓
["AI", "is", "helpful"]
```

The model changes these tokens into numbers because computers work with numbers.

### Embeddings

Embeddings are number patterns that represent the meaning of words or sentences.

For example, the word **bank** can have different meanings:

```text
"I deposited money in the bank."
"People sat near the river bank."
```

The model uses the surrounding words to understand which meaning is intended.

### Attention

Attention helps the model decide which words are important to each other.

```text
"The dog chased the ball because it was moving."

"it" may be connected to "ball"
```

Attention helps the model understand relationships, context, and meaning.

### Transformer

The transformer is the main design used by modern LLMs.

It contains many repeated layers that use:

- Attention.
- Feed-forward processing.
- Position information.
- Learned patterns.

More layers and parameters can improve ability, but they also increase:

- Cost.
- Memory use.
- Energy use.
- Response time.

## 3. How LLMs Learn

### Pre-training

The model first learns general language from a huge amount of text.

This is like learning basic subjects at school.

```text
Books + websites + documents
              ↓
       General language knowledge
```

### Fine-tuning

The model is then trained on more specific examples for a particular task.

This is like going to college to specialize.

```text
General language model
          ↓
Medical data
          ↓
Medical assistant model
```

Fine-tuning can help with:

- Legal documents.
- Medical text.
- Customer support.
- Product information.
- Translation.
- Summarization.

### Transfer learning

Transfer learning means using knowledge learned from a general model for a new task.

Benefits:

- Less training time.
- Lower cost.
- Better results for specialized tasks.
- Less data required.

## 4. Important LLM Principles

### Data-driven learning

LLMs learn patterns from data. Therefore:

> **The quality of the data strongly affects the quality of the model.**

Bad or biased data can produce bad or biased answers.

### Natural Language Understanding

This means understanding what the user says.

Examples:

- Finding the main topic.
- Detecting sentiment.
- Extracting names or dates.
- Understanding a question.

### Natural Language Generation

This means creating a useful response.

Examples:

- Writing an email.
- Creating a summary.
- Answering a question.
- Generating a product description.

### Scalability

A model should continue working when:

- More users arrive.
- More documents are added.
- More requests are sent.
- The company grows.

Larger models may perform better, but making a model larger does not always provide enough improvement to justify the extra cost.

## 6. Types of LLMs

### Public LLMs

Public models are provided through an external service.

**Advantages:**

- Easy to use.
- Fast to start.
- Usually scalable.
- No need to buy expensive hardware.
- Good for general tasks.

**Disadvantages:**

- Less customization.
- Privacy concerns for sensitive data.
- Ongoing usage costs.
- Dependence on the provider.
- Service outages may affect your application.

**Good for:**

- General chatbots.
- Content creation.
- Simple summarization.
- Translation.
- Customer-support drafts.

### In-house LLMs

An in-house model is built or managed by an organization for its own needs.

**Advantages:**

- More control over data.
- Stronger privacy.
- More customization.
- Better for special industry terms.
- More control over updates.

**Disadvantages:**

- Expensive hardware.
- High maintenance cost.
- Requires skilled experts.
- Long training time.
- Difficult to scale without good infrastructure.

**Good for:**

- Healthcare data.
- Financial data.
- Legal documents.
- Private company information.
- Strict compliance requirements.

### Open-source LLMs

Open-source models can be downloaded, changed, and run by organizations.

**Advantages:**

- More control.
- Can run on private servers.
- Highly customizable.
- Often no large license fee.

**Disadvantages:**

- Requires technical knowledge.
- Security is your responsibility.
- Infrastructure can be expensive.
- Performance may need extra tuning.

## 7. Comparison of LLM Types

| Feature | Public LLM | In-house LLM | Open-source LLM |
|---|---|---|---|
| Setup speed | Fast | Slow | Medium |
| Customization | Limited | Very high | High |
| Privacy control | Lower | Highest | High when self-hosted |
| Initial cost | Low | Very high | Low to medium |
| Maintenance | Provider manages it | Organization manages it | Organization manages it |
| Technical skill needed | Lower | Very high | High |
| Scalability | Usually strong | Depends on infrastructure | Depends on infrastructure |

## 8. How to Choose an LLM

Before choosing a model, answer these questions:

### What is the task?

Examples:

- Chatbot.
- Translation.
- Summarization.
- Sentiment analysis.
- Code generation.
- Legal document review.

### How sensitive is the data?

- Public information can often use a public model.
- Private customer or financial data may require a private or in-house model.

### How fast must the answer be?

- Real-time chatbot: low response time is important.
- Overnight report: slower processing may be acceptable.

### How many users will use it?

- A small internal tool needs less scaling.
- A public application needs to handle many users.

### What is the budget?

Consider both:

- Initial cost.
- Long-term running cost.

### How much customization is needed?

- General tasks: public model may be enough.
- Special company tasks: fine-tuned, open-source, or in-house model may be better.

## 9. Important Selection Criteria

### Computational resources

Large models may need:

- Powerful GPUs.
- Large memory.
- Fast storage.
- Cloud infrastructure.
- High electricity usage.

### Scalability

There are two common ways to scale.

**Vertical scaling:**

```text
Use one stronger machine
```

**Horizontal scaling:**

```text
Use multiple machines together
```

### Task-specific performance

A model that is good at writing may not be best at:

- Medical analysis.
- Legal text.
- Translation.
- Sentiment classification.

Always test the model using your actual task.

### Cost

Consider:

- Hardware.
- Cloud usage.
- Model access fees.
- Maintenance.
- Updates.
- Staff.
- Energy.

## 10. Important Evaluation Metrics

Evaluation metrics help us measure how well an LLM performs.

### Perplexity

Perplexity measures how uncertain the model is when predicting the next word.

- Lower perplexity usually means better prediction.
- Higher perplexity means the model is more uncertain.

```text
Model A: Perplexity 30
Model B: Perplexity 80

Model A is usually better for this comparison.
```

Perplexity is useful for comparing models, but it should not be used alone.

### BLEU score

BLEU compares generated text with a reference text.

It is often used for:

- Translation.
- Text generation.

A higher score means the output is more similar to the reference.

### ROUGE score

ROUGE is mainly used for summarization.

It checks how much important wording is shared between:

- The AI summary.
- A trusted reference summary.

### F1 score

F1 combines:

- Precision: How many predicted results were correct?
- Recall: How many correct results did the model find?

It is useful for classification tasks.

### Accuracy

Accuracy means the percentage of correct answers.

```text
100 questions
85 correct

Accuracy = 85%
```

### Human evaluation

People check whether answers are:

- Clear.
- Correct.
- Useful.
- Natural.
- Relevant.
- Appropriate in tone.

Human review is important because numbers cannot fully measure quality.

### Latency

Latency is the time taken to respond.

```text
User asks question → Model answers after 2 seconds
Latency = 2 seconds
```

Low latency is important for:

- Chatbots.
- Voice assistants.
- Live translation.
- Interactive applications.

### Throughput

Throughput is how many requests the model can process in a period of time.

A high-throughput model can handle many users efficiently.

## 11. Other Evaluation Tools

### HELM

HELM evaluates a model across several areas instead of using only one score.

### GLUE and SuperGLUE

These are collections of language tests covering tasks such as:

- Sentiment analysis.
- Question answering.
- Understanding sentence relationships.

### Eleuther’s test

This is another collection of tests used to compare language models.

### Loss

Loss measures how far the model's prediction is from the correct result.

Lower loss usually means the model is learning better.

## 12. Intrinsic and Extrinsic Evaluation

### Intrinsic evaluation

This checks the model’s internal language ability.

Examples:

- Perplexity.
- BLEU.
- ROUGE.
- Grammar.
- Coherence.

```text
Question:
Can the model predict and generate language properly?
```

### Extrinsic evaluation

This checks how useful the model is in a real application.

Examples:

- Customer questions solved correctly.
- Sentiment classification accuracy.
- User satisfaction.
- Task completion rate.
- Number of successful translations.

```text
Question:
Does the model solve the actual business problem?
```

### Simple comparison

| Evaluation type | What it checks | Example |
|---|---|---|
| Intrinsic | General language quality | Perplexity |
| Extrinsic | Real-world usefulness | Customer-support success rate |

Both are necessary.

## 13. Choosing the Right Metrics

Different tasks need different measurements.

| Use case | Important measurements |
|---|---|
| Customer chatbot | Accuracy, latency, user satisfaction |
| Translation | BLEU, human review, meaning accuracy |
| Summarization | ROUGE, correctness, completeness |
| Sentiment analysis | Accuracy, precision, recall, F1 |
| Voice assistant | Latency, accuracy, task completion |
| Report generation | Coherence, factual correctness, cost |
| Healthcare assistant | Accuracy, safety, privacy, compliance |

### Example

For an e-commerce chatbot:

```text
Main goals:
- Answer correctly.
- Respond quickly.
- Solve the customer's problem.
- Keep cost under control.

Useful metrics:
- Answer accuracy.
- Response time.
- Customer satisfaction.
- Task completion rate.
- Cost per request.
```

A high BLEU score alone does not prove that the chatbot is useful.

## 14. Metric Tradeoffs

### Accuracy vs. speed

A larger model may be more accurate but slower.

```text
Large model:
More accurate, slower, more expensive

Small model:
Less accurate, faster, cheaper
```

### Cost vs. performance

The best model is not always the largest one. A smaller model may provide enough quality at a much lower cost.

### Quality vs. scalability

A model may work very well for a few users but slow down when thousands of users arrive.

### Example

For a live chatbot:

- Choose low latency.
- Accept slightly lower accuracy if the answer is still useful.
- Use a larger model only for difficult questions.

## 17. Final Memory Guide

Remember:

- An LLM learns patterns from large amounts of text.
- Transformers and attention help it understand context.
- Pre-training gives general knowledge.
- Fine-tuning adapts the model to a specific task.
- Public models are easy to use but offer less control.
- In-house models offer privacy and customization but cost more.
- Open-source models offer flexibility but need technical skills.
- Choose models based on task, privacy, speed, scale, and cost.
- Use both automated metrics and human review.
- Intrinsic evaluation checks language ability.
- Extrinsic evaluation checks real-world usefulness.
- The best model is not always the biggest model.

> **A good LLM is the one that solves your real problem with the right balance of quality, speed, privacy, scalability, and cost.**
