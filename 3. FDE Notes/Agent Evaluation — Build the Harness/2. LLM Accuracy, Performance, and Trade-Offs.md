# LLM Accuracy and Performance

This course explains how to check whether an LLM is giving good results and how to choose the right model for a real project.

The main idea is:

> **The best LLM is not always the biggest one. Choose a model that gives the required quality at a reasonable cost and speed.**

## 1. Main Trade-Off

A model can be:

- More accurate but expensive.
- Faster but less powerful.
- Larger but slower.
- Smaller but cheaper.
- More private but harder to manage.

```text
Better quality
     ↑
     │   Large model
     │   More accurate
     │   More expensive
     │
     │   Small model
     └────────────────→ Faster and cheaper
```

The correct choice depends on the task.

## 2. Precision

**Precision** means how often the model is correct when it predicts a positive result.

### Example

A spam filter marks 10 emails as spam.

- 8 are really spam.
- 2 are normal emails.

```text
Precision = 8 / 10 = 80%
```

### Easy meaning

> **When the model says “yes,” can I trust it?**

### Useful for

- Spam detection.
- Content moderation.
- Fraud alerts.
- Blocking harmful content.

High precision reduces false alarms.

## 3. Recall

**Recall** means how many real positive cases the model successfully finds.

### Example

There are 10 real fraud cases.

- The model finds 8.
- It misses 2.

```text
Recall = 8 / 10 = 80%
```

### Easy meaning

> **Did the model find most of the important cases?**

### Useful for

- Disease screening.
- Fraud detection.
- Security monitoring.
- Finding urgent issues.

High recall reduces missed cases.

## 4. Precision and Recall Trade-Off

| Priority | Model behavior | Main risk |
|---|---|---|
| High precision | Flags only cases it strongly believes are positive | May miss some real cases |
| High recall | Flags many possible positive cases | Creates more false alarms |

### Example

For disease screening, high recall is often more important because missing a real illness can be dangerous.

For spam detection, high precision may be more important because normal emails should not be wrongly marked as spam.

## 5. F1 Score

**F1 score** combines precision and recall into one score.

It is useful when both false alarms and missed cases matter.

\[
F1 = \frac{2 \times Precision \times Recall}{Precision + Recall}
\]

### Easy meaning

> **F1 shows how well the model balances correctness and coverage.**

If precision is high but recall is very low, the F1 score will still be low.

### Example

One model marks almost every review as positive:

- Recall is high.
- Precision is low.
- F1 score is only average.

Another model correctly identifies both positive and negative reviews:

- Precision is good.
- Recall is good.
- F1 score is higher.

The second model is better for balanced tasks such as sentiment analysis.

## 6. Accuracy

**Accuracy** means the percentage of all predictions that are correct.

```text
100 predictions
90 correct

Accuracy = 90%
```

### Why accuracy can be misleading

Suppose 95 out of 100 emails are normal.

A model marks every email as normal:

```text
Accuracy = 95%
```

But it finds no spam at all.

Therefore, accuracy should be checked together with:

- Precision.
- Recall.
- F1 score.

## 7. Perplexity

**Perplexity** measures how unsure a language model is when predicting the next word.

- Lower perplexity usually means better text prediction.
- Higher perplexity means the model is more uncertain.

```text
Model A: Perplexity 25
Model B: Perplexity 70
```

For the same test data, Model A usually predicts the next word better.

### Perplexity helps measure

- Fluency.
- Smooth writing.
- Logical text flow.
- Understanding of language patterns.

### Limitation

Low perplexity does not guarantee that the model:

- Gives correct facts.
- Reasons correctly.
- Solves the business problem.
- Avoids hallucinations.

It should be used with other tests.

## 8. Which Metric to Use?

| Task | Useful metrics |
|---|---|
| Sentiment analysis | Accuracy, precision, recall, F1 |
| Spam detection | Precision, recall, F1 |
| Medical screening | Recall, precision, F1 |
| Translation | BLEU and human review |
| Summarization | ROUGE and factual correctness |
| Text generation | Perplexity, fluency, diversity |
| Question answering | Accuracy, precision, recall, human review |
| Chatbot | Accuracy, response time, satisfaction |

> **Choose metrics according to the task. No single metric tells the whole story.**

## 9. Large and Small Models

### Large models

**Advantages:**

- Better at difficult questions.
- Understand subtle language.
- Handle many different tasks.
- Often perform better with complex documents.

**Disadvantages:**

- Cost more to run.
- Need more memory.
- Need stronger hardware.
- Use more energy.
- May respond more slowly.

### Small models

**Advantages:**

- Faster.
- Cheaper.
- Easier to deploy.
- Use less memory.
- Can run on smaller machines or devices.

**Disadvantages:**

- May struggle with complex language.
- May understand less context.
- May perform poorly on difficult tasks.

### Example

```text
Simple FAQ chatbot → Small model
Legal contract analysis → Larger model
Mobile assistant → Small model
Complex medical research → Larger model
```

## 10. Computational Cost

Computational cost means the resources needed to:

- Train a model.
- Fine-tune a model.
- Run the model.
- Store the model.
- Serve many users.

Large models usually need:

- Powerful GPUs.
- More memory.
- More storage.
- More electricity.
- More money.

### Ways to reduce cost

- Use a smaller model.
- Start with a pre-trained model.
- Fine-tune instead of training from zero.
- Use model distillation.
- Process many requests together.
- Use efficient training settings.
- Cache repeated answers.
- Use a bigger model only for difficult questions.

## 11. Fine-Tuning

**Fine-tuning** means adapting an existing model to a specific task.

```text
General model
      ↓
Company-specific examples
      ↓
Specialized model
```

### Example

A general model is trained further with:

- Product descriptions.
- Customer-support conversations.
- Company policies.
- Brand writing examples.

It may then give better answers for that company.

### Benefits

- Better accuracy.
- Better understanding of special terms.
- Lower cost than training from the beginning.
- Faster development.
- Better fit for business needs.

### Fine-tuning process

```text
Collect useful data
        ↓
Clean and label the data
        ↓
Choose a pre-trained model
        ↓
Train it on the special data
        ↓
Test it on new data
        ↓
Save and use the improved model
```

### Risks

- Poor data creates poor results.
- Biased data creates biased results.
- Too much training causes overfitting.
- Training needs time, hardware, and skill.

## 12. Overfitting

Overfitting happens when a model memorizes training examples instead of learning general patterns.

```text
Training data result: Very good
New data result: Poor
```

### Example

A model memorizes old customer reviews but fails when customers use different words.

### How to reduce it

- Use varied data.
- Test with new examples.
- Use a small learning rate.
- Stop training at the right time.
- Evaluate regularly.
- Keep training and testing data separate.

## 13. Public and In-House Models

### Public model

A provider hosts the model and your application uses it through an API.

**Good when:**

- You need quick setup.
- You have limited hardware.
- You need general capabilities.
- You want lower initial cost.

**Risks:**

- Less control over privacy.
- Limited customization.
- Ongoing usage fees.
- Dependence on the provider.

### In-house model

Your organization runs and manages the model.

**Good when:**

- Data is very sensitive.
- You need strong privacy.
- You need deep customization.
- You have enough money and skilled staff.

**Challenges:**

- Expensive hardware.
- High maintenance cost.
- Longer setup time.
- Need for specialized experts.

| Factor | Public model | In-house model |
|---|---|---|
| Setup | Fast | Slow |
| Initial cost | Lower | Higher |
| Privacy control | Lower | Higher |
| Customization | Limited | High |
| Maintenance | Mostly provider-managed | Your team manages it |
| Best for | General tasks | Private and specialized tasks |

## 14. How to Choose an LLM

```text
Define the task
      ↓
Decide required accuracy
      ↓
Check data privacy needs
      ↓
Estimate users and traffic
      ↓
Set speed requirements
      ↓
Calculate budget
      ↓
Test different models
      ↓
Compare quality, cost, and speed
      ↓
Choose the best balance
```

Ask:

- What must the model do?
- How accurate must it be?
- Is the data private?
- How fast must the answer be?
- How many users will use it?
- How much can the organization spend?
- Is customization required?

## 15. Overall Output Quality

A good answer should be:

### Coherent

The answer should be logical and well organized.

### Fluent

The answer should sound natural and grammatically correct.

### Relevant

The answer should directly address the question.

### Appropriate

The answer should match the audience, situation, and safety rules.

### Example

An answer can be grammatically perfect but still poor if it:

- Does not answer the question.
- Uses an unsuitable tone.
- Gives unrelated information.
- Gives unsafe advice.

## 16. Simple Evaluation Code

```python
from sklearn.metrics import (
    accuracy_score,
    precision_score,
    recall_score,
    f1_score
)

actual =    [1, 1, 0, 0, 1, 0]
predicted = [1, 0, 0, 0, 1, 1]

print("Accuracy:", accuracy_score(actual, predicted))
print("Precision:", precision_score(actual, predicted))
print("Recall:", recall_score(actual, predicted))
print("F1 score:", f1_score(actual, predicted))
```

Here:

- `1` means positive.
- `0` means negative.
- `actual` contains the correct answers.
- `predicted` contains the model's answers.

This gives a better view of model quality than looking at only one result.

## 17. Best Evaluation Method

Use several checks together:

```text
Automated scores
       +
Human review
       +
Real-world testing
       +
Speed and cost checks
       +
Safety and bias checks
```

Also test:

- Normal examples.
- Difficult examples.
- Rare cases.
- New data.
- Long inputs.
- Different user groups.
- Unexpected or tricky inputs.

## 18. Final Memory Guide

- **Precision:** When the model says “yes,” how often is it correct?
- **Recall:** How many real “yes” cases did it find?
- **F1 score:** How well does it balance precision and recall?
- **Accuracy:** How often is it correct overall?
- **Perplexity:** How uncertain is it when predicting text?
- **Large model:** More power, but higher cost and slower speed.
- **Small model:** Faster and cheaper, but less capable.
- **Fine-tuning:** Adapt a general model for a special task.
- **Public model:** Easy and quick to use.
- **In-house model:** More private and customizable, but expensive.

> **Choose an LLM by balancing quality, speed, cost, privacy, and the actual needs of the task.**
